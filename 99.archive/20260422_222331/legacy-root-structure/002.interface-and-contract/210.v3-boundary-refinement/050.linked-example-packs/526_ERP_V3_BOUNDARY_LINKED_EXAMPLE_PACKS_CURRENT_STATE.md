# ABSTRACT

Defines the current state for the first linked
example-pack materialization pass under the
promoted ERP v3 boundary refinement program.

The prior pass created:
- explicit boundary registry entries
- explicit entry template
- reconciliation-facing extension direction
- linked example pack policy

This pass converts the first reserved rule IDs
into concrete example-oriented explanatory packs.


# WHY THIS PASS EXISTS

A boundary rule becomes more reviewable when it is
supported by at least one representative scenario.

This pass exists to ensure the promoted boundary
rules are not only registry-safe, but also
interpretation-safe.

# DESIGN ROLE OF EXAMPLE PACKS

Example packs are explanatory design objects.

They are not:
- database fixtures
- executable test cases
- implementation mappings
- silent redefinitions of the rules

They exist to clarify how a boundary rule behaves
in realistic or high-leverage situations.


# REQUIRED RESULT

After this pass, the corpus should have:

- one first-wave example pack per high-priority rule
- explicit mismatch variants
- explicit reconciliation variants
- explicit anti-misreading notes
- root-connected continuation after 525


# CONSTRAINTS

Do not let one scenario overfit or narrow the
meaning of a more general rule.

Do not let example narratives silently transfer
truth ownership across domains.

Do not confuse an explanatory scenario with
implementation detail.
